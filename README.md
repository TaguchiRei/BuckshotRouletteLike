# BuckshotRouletteLike

## 概要

本プロジェクトは、インディーゲーム **Buckshot Roulette** を参考にして制作したゲーム習作プロジェクトです。
ゲームエンジンには **Unreal Engine** を使用し、主に **Blueprint を中心としたゲームロジック実装の学習** を目的として制作しました。

ゲームの完成度を目的とするものではなく、以下のような技術的な学習を目的としています。

* Unreal Engine におけるゲームロジック構築
* UI 実装
* Blueprint による状態管理

---

## 参考ゲーム: Buckshot Roulette

**Buckshot Roulette** は、インディー開発者 Mike Klubnika によって制作されたホラー系テーブルトップゲームです。
2023年に公開され、2024年には Steam 版もリリースされました。

### ゲーム概要

* ロシアンルーレットをベースにしたゲーム
* 通常のリボルバーではなく **ショットガン** を使用
* プレイヤーは **ディーラーと交互に引き金を引く**
* 弾は **実弾と空砲がランダムに装填** される
* 誰に撃つか（自分 / 相手）を選択する

実弾の場合はライフが減少し、
空砲で自分を撃った場合は **追加ターン** を得ることができます。

また、ゲームにはアイテムやライフ管理などの戦略要素があり、
**運要素と心理戦が組み合わさった緊張感の高いゲームプレイ**が特徴です。

## このプロジェクトで学んだこと

### 1. Blueprintによる複雑な状態管理の危険性

Blueprintのみで複雑な状態管理を実装すると、
ノード接続が大量に発生し、可読性や保守性が急激に低下することが分かりました。

主な問題

* 状態遷移の追跡が困難になる
* ノード接続の把握が難しくなる
* バグの原因特定が難しくなる

そのため、**状態管理が複雑になる場合は設計段階で構造を整理することが重要**であると学びました。

---

### 2. 共通機能を持つオブジェクトのベースクラス設計

同様の機能を持つオブジェクトを多数作成する場合、

1. **ベースクラスを作成**
2. それを継承したクラスを作成

という構造が有効です。

Unreal Engine では

* 通常の **Blueprint を親クラスとして利用することも可能**

であるため、
最初から抽象的なベースクラスを作るのではなく、
**実装済みの Blueprint をベースとして派生クラスを作る方法**も有効であると学びました。

---

### 3. UIとボタンの設定

UI要素（ボタンなど）は、
**プレイヤーにアタッチする形で管理する必要があるケースが多い**ことが分かりました。

特に以下の要素で設計が重要になります。

* UI生成
* 入力受付
* プレイヤー操作との連携

そのため、
**プレイヤーとUIの関連付けを明確にする設計**が必要であると学びました。

---

### 4. ビルド後にUIボタンが押せなくなる問題

開発環境では問題なく動作していても、
**ビルド後のゲームで UI ボタンが反応しなくなる問題**が発生する可能性があります。

考えられる原因の例

* Input Mode の設定
* UI Focus の問題
* Widget の生成タイミング

そのため、
**パッケージビルド後の実行環境での動作確認が重要**であることを学びました。

---

## まとめ

このプロジェクトでは **Buckshot Roulette** を参考にしながら、
Unreal Engine の Blueprint を用いたゲーム開発の基礎を学習しました。

特に以下の点について理解を深めることができました。

* Blueprintによるロジック設計の限界
* 継承構造を利用したクラス設計
* UIとプレイヤーの関係設計
* ビルド環境と開発環境の挙動差

ゲーム制作において **設計段階の重要性と Blueprint の扱い方**を学ぶための習作プロジェクトです。
